**agent-ops** is the control plane for a small fleet of AI-driven pipelines. It doesn't ship a product of its own — it orchestrates work across other repositories: planning and implementing GitHub issues, running end-to-end tests, generating documentation sites, and running a personal job-search assistant.

## How it fits together

- **Orchestrator** — an Express service (built on the published `@heyitschloe/pipeline-orchestrator` engine) that reads GitHub events and dispatches pipelines. One unified registry, `orchestrator/src/registry/pipelines.yaml`, defines every pipeline; adding one is a new registry entry, not new engine code.
- **Pipelines** — the dev-ticket pipeline (plan/implement issues in app repos), the in-process job-search pipeline, plus the shared reusable e2e and wiki workflows.
- **Model gateway** — a LiteLLM instance on Cloud Run. Every component calls a model *alias* (planning, implementation, classification, documentation), never a provider SDK directly, so the model behind an alias is a one-line swap.
- **Skills** — reusable, `applies_to`-matched instructions the pipelines load at runtime.
- **This docs site** — generated by agent-ops's own shared wiki generator from the repo's source, with the narrative you're reading authored on top.
